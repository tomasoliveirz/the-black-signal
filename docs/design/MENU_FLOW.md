# Room flow refinement contract

Source: the owner's quality-reset directive, BS-UX-01. Operate mode. Preserve the current low-light game backdrop, Fraunces title voice, IBM Plex controls and warm neutral/gold system. This is task separation inside the established game menu, not a replacement visual identity or a claim of approved environmental art.

Home explains the verified six-player premise and takes the player to Play. Play contains public-room discovery, private invitation and public/private creation, with map previews behind a disclosure. A joined player opens Room automatically: map choice and roster/preparation/chat are in separate columns at desktop widths. Home, Room, How to Play, Settings and Account remain reachable through persistent navigation. Inactive views use the native hidden state; keyboard focus follows deliberate navigation. Returning/leaving must not leave stale membership or hide errors.

Room starts only after every seated human is ready and the host sends Start. The authoritative phase event enters play. A map change resets readiness. Non-hosts see selection locked; spectators do not block seats. Settings alone carries quality/audio/microphone controls; opening it never grants microphone consent. English and pt-PT cover all new copy, and user names/chat are not translated.

Required verification: desktop 1440×900, mobile menu 390×844, EN/PT; private invite, public creation/list/join, host/non-host, ready withdrawal/start, menu return/leave, guide tab keyboard, settings controls, account access, room-list empty/error, long names and text, no horizontal overflow/runtime/request failures. Mobile screenshots validate menu layout only; the game still needs keyboard/mouse controls. Six-human unassisted onboarding remains an independent gate.

Non-goals: account recovery/moderation redesign, new game mechanics, changed map/resource/phase balance, new art assets or production deployment. Rollback this thematic UI commit; the separate readiness protocol remains available in its own PR.
